# 小さい作業領域での操作

ウィンドウ外寸は[共通サイズ制御](window-sizing.md)が画面の論理visualBoundsへ収めます。画面内の内容にはスクロールと操作列の折返しを使用し、文字や画面全体の倍率は変更しません。

- モード選択は縦スクロールで最後の選択肢へ移動できます。developmentの管理テスト環境入口にも同じ構成を使います。
- Editorの外枠スクロールには上部メニューとサイドバーを含めます。中央編集領域のスクロールも使用できます。狭い幅では横スクロールで左右の領域へ移動します。
- Simulatorの装備選択・計算・詳細ページ・比較操作は必要に応じて折り返します。入力領域、詳細、比較内容の既存スクロールを使い、外側のスクロールから各領域へ移動できます。
- 入出金・実績・ショップ履歴の検索条件は折り返し、各タブの縦スクロールから一覧まで移動できます。
- ServerControlは設定・保存・実行結果を含む画面全体をスクロールできます。Console、ModConfigの操作列は幅に合わせて折り返します。
- 編集補助ダイアログは本文をスクロールできます。独自Stageのダイアログでは決定・取消も本文と一緒にスクロールし、標準Dialogでは決定・取消を本文の外に保持します。

保存形式、計算処理、通信処理、キーボードショートカットは変更しません。FXMLのfx:id、イベント名、Controllerのフィールド型を維持します。ScrollPane内の内容を描画前に参照するテストではFXMLLoaderのnamespaceを使用します。

## 検証の記録

Windowsの実Stageテストで、primaryの論理visualBoundsは2560×1392、outputScaleは1.0でした。OSの解像度・DPI設定を変更せず、装飾付きStageを次のサイズへ変更しました。これらは小さい論理ウィンドウでの検証であり、別の物理解像度やDPI設定の実測には代用しません。

| 900×460 | 884×421 | 通常の縮小 |
| 600×400 | 584×361 | さらに小さい領域への縮小 |
| 660×420 | 644×381 | サーバー選択は既存の最小外寸に制限 |

小画面の新規4テスト、development入口の1テスト、既存サイドバーの2テストはWindowsで成功しています。実4種別Editorは900×460で一覧・中央編集領域と保存メニューを確認しました。

実FXMLの必須操作ID、折り畳み領域の展開、履歴タブの切替、入力の存在・祖先を含む可視性と有効性・Scene内の論理フォーカス、ボタン全体の表示を確認します。画面外にある操作は除外せず、各スクロールを動かして到達を確認します。補助ダイアログは600×400のStageで決定・取消を実行します。論理フォーカスはSimulator・ServerControl・入出金履歴・サーバー作成／編集の必須入力について、requestFocus後のScene.focusOwnerで確認します。未接続のConsoleコマンド入力は、存在・到達と意図的な無効状態を確認します。接続中のConsoleの実入力は未検証です。Windowの活性を必要とするNode.isFocused、実入力・IME・クリック・Tabによる操作は、このレイアウトテストとは分けて記録します。
