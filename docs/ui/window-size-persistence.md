# ウィンドウサイズの保存と復元

`Utility.createScene`は通常画面の`AppScreen.name`を保存キーとします。`BASE`と`WIDGETS_ONLY`は既定では対象外です。Editorは`windowKey`に既存のEditor種別キーを渡します。サーバー名やデータIDはキーに含めません。履歴画面は各タブを同じウィンドウで表示するため、`MONEY_HISTORY`の1キーで保存します。

保存先は`config.json`の`windowSizes`です。各値は`width`・`height`・`maximized`を持ち、幅高は装飾込みの論理座標です。旧configでは空Mapとなり、正常にデコードできたAppSettings内の未保存または非正・非有限の幅高は共通初期値で開きます。位置、画面ID、最小化、フルスクリーン状態は保存しません。

通常外寸をshow前に復元し、共通サイズ制御による表示後補正を終えてから最大化します。最大化・最小化・フルスクリーン中の外寸は通常寸法へ取り込みません。解除時には保持した通常外寸を要求し、その後の通常リサイズを記録します。遅延処理で新しいリサイズを上書きしません。

`WINDOW_HIDING`で通常寸法を確定して記録を止め、`WINDOW_HIDDEN`の追加ハンドラで保存だけを行います。再表示では`WINDOW_SHOWING`で通常外寸を適用し、新しいnativeウィンドウの初期サイズへ渡します。取消されたclose要求では保存せず、同じキーは最後に非表示になったウィンドウの値を採用します。JavaFXスレッド上で最新のAppSettingsを読み、対象キーだけ更新して保存するため、サイドバー展開やUUID表示等を保持します。保存I/Oは既存の設定ハンドラへ委譲し、失敗で終了を妨げません。

通常画面から準備Sceneへ切り替えるときは、`WindowSizePersistence.suspend(stage)`をScene代入前に呼びます。通常寸法を確定して記録を止め、非表示時には確定値を保存します。同じStageで通常画面へ戻る場合もこの確定値を使い、準備画面の420×140を通常寸法として保存しません。

JavaFXのStage幅高setterはプロパティを即座に更新しますが、nativeへの反映とは別です。実表示の検証ではScene実寸への反映を観測してから最大化等へ切り替えます。同じFXターンでの明示寸法要求は別のAPI順序として検証します。

設定ファイル自体がデコード不能な場合は、既存のJsonFileHandlerの契約どおりAppSettings全体の既定値を使います。例えばDoubleの範囲を超える`1e309`はJSONデコーダーの有限値制約により拒否されます。これはデコード済みWindowSizeの無効寸法を除外する処理とは別で、設定の一部を救済する修復処理は追加していません。通常の画面保存では有限かつ正の寸法だけを出力します。
