WindowsのJDKは21.0.9です。JavaFXからは2560×1440の3画面、各visualBounds 2560×1392、dpi 108、outputScale 1.0×1.0を観測しました。負座標の画面を含む移動・再表示・最大化解除に成功しました。異種拡大率やhotplugは確認していません。通常の11skipはmacOS限定8件、native操作1件、ローカル条件1件、SFTP環境未指定1件です。developmentの15skipは管理接続・実Mod・SSH環境の未指定によるものです。

Windowsの最終Formula4件、macOSの関連48件、両OSの全buildに統合テストが含まれます。到達性はScrollPaneが扱うレイアウト座標で判定し、比較本文の先頭・末尾、入力変更後のFinished説明保持も確認します。全build後の追加変更はこの受入記録だけです。JUnit XML、実行ログ、source lock、別JVMのPID/終了コードと設定hashをタスク証跡に保全しました。

macOSはJDK21.0.9/aarch64です。隔離設定の別JVM確認は、外部probeの終了処理を次のFXターンへ送る版で保存・復元・最大化解除を確認し、2プロセスともexit0、PID終了、例外なしでした。通常740×520と最大化状態を保存し、次JVMで復元して通常740×520・最大化解除を保存しました。タイムアウトと終了例外の原本は別に保全しています。製品コードを変更せず、終了順序を修正したprobeの結果として区別します。

FXML自己StageのNode操作・表示到達性と、native入力や人によるGUI確認は別です。skipと個別Issueの失敗原本を残し、未実施を成功扱いにしません。統合状態のサイズ補正と全buildは両OSで成功しました。個別失敗の原因は結果だけから断定しません。

## 正式配布の準備と残作業

正式依存候補は`io.github.sushiericworkspace:sushieric-datamodel:1.0.0`と`io.github.sushiericworkspace:sushieric-combat-core:1.0.0`です。[既存の成功run](https://github.com/SushiEricWorkspace/SushiEricServerManager/actions/runs/38887130474)の両OSログで、各正式版1.0.0と上記source commitを確認しました。Managerの[公開v1.0.0](https://github.com/SushiEricWorkspace/SushiEricServerManager/releases/tag/v1.0.0)には両OSのInstallerがあります。DataModel/Coreの独立したv1.0.0 Releaseは確認できず、workflowは固定sourceから`publishRelease`して組み立てます。

今回の開発受入で用いるdev artifactのhashは正式配布artifactのhashではありません。正式ビルド時は両依存の版・完全source commit・CoreのDataModel座標、CIの整合性検査成功、runと取得可能なruntime JAR・配布物のhashを照合します。既存workflowはPOMをartifactへ出さないため、正式POM hashは未取得として扱います。開発用POM hashを正式POMの実測へ流用しません。正式依存の再発行、CI、jpackage、main反映、tag、asset/Release公開は個別の許可後に[リリースガイド](../update/release-guide.md)に沿って実施します。

Release説明案: 小さい画面でもEditorやシミュレーターの主要操作へ移動できるよう改善しました。画面種別ごとのサイズと最大化状態を保存・復元します。戦闘シミュレーターに計算式と、最後の計算要求に対応する説明を追加しました。入力を編集した後も、計算済みの結果と説明を確認できます。
