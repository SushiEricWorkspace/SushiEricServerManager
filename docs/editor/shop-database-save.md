# 商品定義とDB在庫の保存

編集内容は保存元別のローカル文書世代へ保存し、明示アップロードだけをDataModelのD3へ渡します。定義hashはProductsで読み込んだ元bytes、在庫は最新quantity/revisionを使います。ローカル文書revisionや再serializeした定義hashで代用しません。

## 通常Local/SSHのHost接続

非秘密参照と固定helper配置は[履歴のDB読取](history-database-read.md)と共通です。`LocalShopTransport`と`SshShopTransport`は同じフレーム式`PostgresWriterCli`へ接続し、同じ編集接続の商品・履歴で一つのHをOpenからCloseまで共有します。複数の正常なEdit/Readと履歴ページは同じHで直列に実行します。検索の終了ではHを閉じず、接続終了で閉じます。SAVEDのrun hash/state revisionを次の読取へ引き継ぎます。SAVEDはHostの完成記録を表し、process終端やsnapshot適格を意味しません。

Manager自身はJDBC接続・secret file読取を行いません。helperが固定保護設定とcurrent/bindingを検査します。URL/conninfo/追加Properties・別DB/role/passfileを要求へ注入できません。SFTPへの商品書戻しやDBコピーで失敗を迂回しません。

通常SSHの商品経路は最初の要求でManagementか固定Hostに決め、同じ編集接続の途中では切り替えません。v2 profileで旧Management DB契約を使うことは拒否します。型付きManagementはMod #631、managedは.github #148/#64の確定成果へ後続接続します。

## 要求と保存待ち

`ShopSavePlan`の定義hashと在庫revisionをそのままHostAdapterRequestへ固定します。在庫未変更はUnchanged、明示変更はSet(quantity, revision)、初期登録はRegisterです。未初期化と無限在庫を区別し、価格だけの保存で在庫値を再適用しません。IDと定義の同時変更はSave+Deleteの親要求です。

`ShopSaveSession`は送信前に元要求をforceし、同じdirectoryの保存待ちfileへatomic moveします。PGの保存待ちはstorageContractVersion=2、固定PostgresRunBinding、元Host要求を持ちます。別DB/world/generation・旧payloadの照合は送信前に拒否し、元bytesを保持します。旧保存待ちのPGへの自動変換は行いません。

準備済みアップロード工程にも`productBinding`を保持し、送信・結果照合のどちらでも現在のDB/world/generationへ一致させます。bindingのない旧工程をPGへ自動適用せず、台帳と保存済み本文を保持します。適用先を改めて確認して工程を準備する必要があり、旧工程へ値を補完する移行は行いません。worldなし編集backupと旧非PG工程にはこのfieldを出力しません。

Hostの不明応答、不正応答、接続断、timeout、容量・ACL・admissionの失敗では元要求を保全します。PG Hostの理由を特定できないREJECTEDも保存待ちを削除しません。未確認要求がある間は新規Editを拒否します。editing/original、保存済みチェックポイント、未保存の入力はローカル文書が保持します。

新規保存・削除では保存待ちfileの存在だけで停止し、旧形式や別世代のpayloadをエラー分類のために再解釈しません。直接のRemote保存も`PENDING_REVIEW`のFailureを返し、元bytesとbackupを維持します。明示照合時だけ保存済みbindingと元要求を検査します。

## read-onlyの結果照合

明示的な結果確認はwriterをdrain/終了してから、同じ固定配置の`PostgresOfflineLookupCli`へ元要求を一回だけstdinで渡してEOFにします。Editの再送は行いません。元IDとDataModelの正規化request hash、CLI終了値を照合します。非秘密currentの前後観測でbindingとrun hashも比較し、別世代や観測中の変更を拒否します。

COMPLETEだけを完成結果として返します。NOT_FOUND、INCOMPLETE、CONFLICT、REJECTED、UNAVAILABLEや終了不明を未適用・再送許可へ読み替えません。部分成功のjournal/DB/fileやrun記録を変更しません。COMPLETEもstart許可ではなく、offline_pendingが残る場合はHostの通常admissionが拒否します。

失敗したHの自動再起動・owner再発行は行いません。照合後の新たな読取・編集には編集接続を作り直し、通常admissionを改めて通します。既存アップロード台帳は完成照合だけで未保存入力や保存済み本文を上書きせず、読戻し未完了ならUNKNOWNを維持します。

## worldなし編集と残件

worldのないLocalEditorDataStoreは商品backupのID・在庫編集値・stockBaselineを保持します。有限・無限・未初期化の意味を変えず、破損backupを通常定義YAMLへ読み替えません。

#243の画面固有の複合編集、ディレクトリ親要求の組立て、定義削除後の残存在庫行を含む競合処理は残件です。Local/SSHの基盤更新でこれらを完了扱いにしません。通常Host配置を設定する専用UIも追加していません。

固定Host ZIP＋PGの試験は連続編集、価格のみ変更、応答喪失後のread-only照合、binding/接続設定の改変、正常保存前・ACL・PG容量失敗を確認します。unitでは元要求とbackup、世代変更、同ID/hash、stdin/EOF・timeout/切断を確認します。実SSH・macOS・Management/managed結合は後続です。
