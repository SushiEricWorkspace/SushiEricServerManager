# 保存済み内容のアップロード

## 確認と反映

「アップロード」は現在のローカル保存済み世代だけを使う。編集中の未保存値や入力途中の数値文字列は送信しない。型付き文書の追加・更新で保存済みの入力退避が残る場合は対象外として理由を表示する。削除は本文や入力退避を送らず、削除意図だけを確認する。ローカル保存とサーバーからの明示取得は別操作のまま維持する。

対象は保存元・種別・完全IDで固定し、最新サーバー内容、取得・反映確認済みの基準、ローカル保存済み内容を比較する。基準未取得では内容と宛先の確認を必要とし、同じ項目の両側変更は本人が選択する。Mod設定は全文を選択し、YAMLの項目別自動統合は行わない。

Itemを先に反映し、参照する定義の更新後に不要なItemを削除する。未選択の参照元も読み、参照を壊す削除は拒否する。改名・移動では旧位置の不存在と新位置の本文を確認する。工程はサーバー側の一括トランザクションではない。SFTPで確認後に他の書込みが入る競合を完全には除外できない。

## 台帳と結果不明

宛先ごとの台帳に固定要求、予約した文書、開始revision、工程と結果を保存する。作用前の台帳保存に失敗した場合は書き込まない。書込応答が不明でも読戻しが一致すれば反映確認できるが、読取失敗や不一致を成功にしない。

結果不明の工程は自動再送しない。「結果を読戻しで確認」で永続化された要求を本人が選び、同じ固定内容へ照合する。要求選択前に凍結対象を追加せず、既存の結果不明による保全は維持する。選択後はその要求に含まれる文書だけを追加の対象として凍結する。読戻しは新しいアップロード要求を作らない。

確認できた工程だけが基準を更新する。台帳・基準・反映済み保存内容の印・対応する保留操作の解除は同じローカル世代で公開する。サーバー書込後にローカルCASが失敗した場合も、サーバー作用が未実行だったとは推定しない。最新台帳を読めない場合は対象の凍結を維持する。

部分移動後に本文更新が失敗し、その間に逆方向へ編集したなど、現在の保留操作を元要求へ一意に結び付けられない状態は作用前に保留する。元要求の工程・理由を確認し、自動修復や別要求で結果不明を飛び越えない。

## 保存元と画面

ローカルから別サーバーへの反映結果は宛先の台帳に置き、共有ローカル文書の基準を混ぜない。宛先に既存の保存済み・編集中・入力退避がある場合は保持し、確認したrevisionと一致する対象だけを更新する。基準だけ存在し保存済み内容がない文書を削除要求として扱わない。

対象文書だけ編集・保存を止め、他の文書の入力、Undo、ローカル保存を継続できる。画面は反映を確認した保存済み内容を識別し、サーバー側だけの変更を再取得で編集層へ差し戻さない。切断・保存元変更後の古い結果を別対象へ適用しない。

## 制約

ShopのDB反映は必要なDB capabilityが未接続のため実行しない。ローカル保存を保持して理由を表示し、旧YAMLへの書戻しや現在在庫のSFTP置換へ切り替えない。

保存元は論理的な文書の帰属であり、実world・DBの同一性の証明ではない。外部SSH設定の変更も自動検出しない。実サーバーの認証・世代確認とDB適用は対応する接続・DB機能の契約が必要になる。

新しい文書世代にはアップロード台帳と反映済み保存内容の印を含む。未リリース形式への互換移行は追加しない。未知の形式・壊れた台帳を推測して公開せず、原本を保持してエラーを返す。
