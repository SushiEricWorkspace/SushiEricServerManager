# エディターのサイドバーと性能確認

## 構成

Item、Ore、Recipe、Shopの一覧は共通の`EditorSidebar`を使用する。検索結果と展開中のディレクトリを`SidebarRow`へ変換し、固定高32pxの`ListView`へ渡す。セルは表示領域に必要な数だけ生成し、スクロール時に再利用する。

選択、変更、検証、ローカル作成、削除予定の状態はデータIDで保持する。セルの再描画は保持した状態を参照し、検証、データ読み込み、履歴記録を行わない。編集時やプリロード完了時の状態更新はエディター側が担当する。

右クリックメニューは現在の行のIDから生成する。ディレクトリ行へのドロップはそのディレクトリへの移動、一覧の空白へのドロップはルートへの移動となる。同じディレクトリへの移動は無効とする。

## 起動と選択

ウィンドウを表示してから、バックアップ復元、一覧とディレクトリ取得、初期データ取得の順に背景で処理する。トップバーに工程を表示し、読み込み中、空一覧、取得失敗を区別する。YAMLの解析と三者間マージは背景で行い、キャッシュの注入、Nodeの生成と更新はJavaFXスレッドで行う。

`setupSidebar`は一覧取得の完了を待たずに戻る。`selectTab`は選択表示をすぐ更新し、最新データの取得中は内容の編集を抑止する。別の項目を選択した場合や画面・接続が終了した場合、旧要求の結果を反映しない。この抑止は実通信の中止を意味しない。取得失敗時も編集キャッシュを維持する。

リモートの選択時は保存先から最新データを取得し、未保存変更があれば元データ・編集中データ・最新データをマージする。保存後の再表示は保存処理で取得済みの一覧とデータを使う。サイドバーの状態確認用プリロードと編集用参照一覧の取得は初期データの表示後に開始し、状態確認は1件ずつ進める。復元途中で閉じた場合は既存バックアップと保留操作を変更しない。

## データ作成とディレクトリ操作

新規作成・複製・ID変更・移動は入力後に最新の一覧で重複を確認する。未取得の複製元は背景で読み込む。データの追加・ID変更・削除は保存まで保留し、表示の更新は取得済み一覧へ保留操作を重ねる。ドラッグ移動の受付後も確認は背景で進み、失敗時は元の編集状態を維持する。

ディレクトリ操作は「確認中」「作成中」「削除中」「一覧更新中」を表示し、ストアの読み書きは接続のI/Oキューで行う。処理中は重複操作・編集・保存・画面終了を抑止する。削除対象は最新の一覧から表示し、UIで承認を受ける。local-onlyディレクトリは編集とバックアップだけを破棄する。

再帰削除が失敗した場合は一覧を再取得し、消失を確認できた保存済みデータだけ編集キャッシュから除く。未確認のデータと保留操作は保持し、自動再試行しない。削除成功後に一覧更新が失敗した場合は、削除済みデータを編集キャッシュから除いて再保存を防ぎ、更新エラーを表示する。

## Windowsでの測定

Issue #228の検証として2026年10月13日に測定した。JDK 21、JavaFX 21.0.1、1000×720のStageを使用し、検索入力直後の同期処理、レイアウト完了、後続イベントまでの時間を記録した。レイアウト完了はJavaFXのレイアウト処理の完了を指し、物理ディスプレイへの描画時間ではない。

- 件数: 100、1,000、10,000件
- 表示: コンボボックス、フラット、2階層ツリー、8階層ツリー
- 検索: 全件一致、1件一致、一致なし、空文字
- 各条件3回ウォームアップ後、12回測定を2巡
- 追加条件: 10,000件それぞれが異なる8階層ディレクトリを持つツリー
- 合計104条件、1,248サンプル。並行して画面テストを実行しない

10,000件・全件一致の同期処理中央値（ms）:

| 表示 | #222での測定 1巡 / 2巡 | 仮想化後 1巡 / 2巡 |
|---|---:|---:|
| フラット | 124.411 / 162.348 | 12.373 / 12.350 |
| 2階層ツリー | 145.386 / 163.561 | 12.310 / 12.870 |
| 8階層ツリー | 194.990 / 253.621 | 30.350 / 27.090 |
| 各IDが異なる8階層ディレクトリ | 未測定 | 46.554 / 48.439 |

全条件で同期処理の最大値は68.871ms、レイアウト完了までの最大値は77.389ms、後続イベントまでの最大値は68.971msだった。同期処理100ms以上のサンプルは0件。

測定用画面は合成IDと状態を使用し、実サーバー通信、データ読み込み、検証処理を含まない。性能測定は標準スキンを使用する。製品FXML・CSSとの接続は別途画面テストで確認した。基準値は[Issue #222の記録](https://github.com/SushiEricWorkspace/SushiEricServerManager/issues/222#issuecomment-6142384461)を参照。

## 確認範囲

- 行モデル: 並び順、折り畳み、空ディレクトリ、検索後の展開状態、フラット表示の完全ID
- 製品FXML・CSS: 10,000件でもセル数50以下、末尾へのスクロール、セル再利用時のID・状態更新
- 4種類の実エディターとメモリ内Store: 検索、選択、検索で隠れた選択状態の復元
- 右クリック: 現在の行のIDを使用し、一覧更新時にディレクトリメニューを閉じる
- 手動操作: 合成データの確認画面でディレクトリへ移動後、空白へのドロップでルートへ戻ることを確認。操作ログでも両方の移動先を確認

JavaFX Robotによるネイティブドラッグは、この環境ではマウス入力イベントが画面へ届かず自動確認できなかった。対応テストは`sidebar.nativeRobot=true`を明示した場合だけ実行する。手動確認の成功を自動テストの成功として扱わない。macOSでの画面確認は未実施。
