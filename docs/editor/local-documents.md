# 編集・ローカル保存・取得基準

## 保存元と文書

文書は保存元、データ種別、完全IDで識別する。ローカル保存元はオンラインとオフラインで共有する。サーバーの作業コピーはprofile UUIDと宣言された接続先を保存元とし、同じIDでもローカルや別の接続先とは編集キャッシュ、参照一覧、Undo/Redo、入力退避を共有しない。保存元は各エディターとMod設定のメニューで選択する。

通常SSHの接続先にはhost、port、user、rootを含める。profileの表示名変更ではUUIDを維持し、既存profileに欠落するUUIDは元設定を保全してから保存する。設定の削除と再作成では新しいUUIDになる。

管理接続では既存profileの識別子と宣言host/user/root/instanceIdから論理保存元を決める。binding、lease、run、sessionを文書の帰属に使わない。SSH設定ファイルの外部変更や実worldの再作成を自動検出する識別ではない。サーバーへ適用する処理は、この保存元と取得基準だけを実対象の同一性証明に使わず、実対象・world・世代・revisionを別途照合する必要がある。

## 三つの状態

- 編集中: typedデータ、入力途中の文字列、作成・ID変更・削除の保留操作。
- ローカル保存済み: 明示的な保存が成功したチェックポイント。入力途中の文字列も同じ世代に保存する。
- サーバー基準: 最後に取得した、または反映を確認したデータ。基準未取得と、取得して不存在を確認した状態を区別する。

未保存表示は編集層と保存済み層の差を示す。保存すると未保存は解消するが、サーバー基準との差は解消しない。サーバーの作業コピーでは未アップロード、基準との一致、基準未取得を別に示す。サーバー基準のないローカル文書に一致状態を捏造しない。

数値へ変換できない入力は、最後のtyped値へ置き換えず、保存元・種別・IDと安定した欄のキーで保持する。不正入力を保存しても有効なtyped入力へ昇格させない。文書のUndo/Redoはtypedデータと入力途中の文字列を一緒に復元する。IMEの未確定入力は確定・取消まで履歴へ追加しない。Mod設定はYAML構文や値を解析せず、生テキストを同じ三層で保持する。

## 保存と取得

保存・すべて保存はローカルだけに書く。通信の書込許可、接続継続、サーバー上の在庫値を保存条件にしない。アップロードへの代替や、保存時の自動再取得は行わない。コマンド実行、起動停止など即時操作の通信契約は別である。

明示取得では最新データを読み、取得基準の更新を確認する。未送信のローカル保存済み内容は保持し、比較元がある編集内容は既存の三方向マージと競合選択で統合する。比較元がない文書は自動統合せず、ローカル内容を保持して基準だけ更新することを確認する。取消や取得失敗では基準を進めない。空ディレクトリもローカル保存済み一覧と取得基準との差から追加・削除を保持する。取得開始時のディレクトリrevisionが変わった場合は、確認した一覧で新しい変更を上書きしない。

Mod設定の「再読み込み」はローカル保存済み本文へ戻す。「サーバーから取得」は別の確認操作で基準を更新し、未送信の保存済み本文と編集中の不正テキストを保持する。本文をYAMLとして自動統合しない。

ローカルから別の作業コピーへ取り込む場合も、同じ保存世代のtypedデータと入力退避を一緒に渡す。取込元は保持し、取込先は未保存の編集として扱う。

サーバーへのアップロードと最新DB在庫の反映は独立した処理である。古いローカルの在庫値を最新DBへ書き戻す処理をここでは追加しない。

## 世代の公開と復元

アプリのautosave配下のdocumentsに、保存元別の不変JSON世代とcurrentを置く。カスタムautosave rootでも文書とcodecはその所有領域内に閉じる。管理接続のLocal文書は正式なアプリ保存領域を明示し、binding用作業領域とは分離する。

同じ保存元の保存・退避・Modテキスト・ID変更はI/Oキューとpublisherのファイル排他で直列化する。同じcanonical保存領域では、channelのopenからcloseまでJVM内でも排他する。[JDK25のFileLock仕様](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/nio/channels/FileLock.html)のJVM内・OS依存の制約を踏まえ、FileLockだけをスレッド排他として扱わない。

各編集画面が読み込んだ文書revisionを保持し、その画面の成功した書込みだけで前進させる。別画面や別プロセスが更新したrevisionへ黙って追随せず、古い編集の保存・退避を拒否して画面内のdraftを保持する。未作成文書のrevisionは0とし、変更した文書だけを最新世代へ合成する。ID変更では旧IDと新IDを同じ世代で公開する。成功世代をforceした後、currentをatomic moveする。atomic moveに対応しない場合は失敗として保持し、非atomicの代替で成功扱いにしない。

退避の解除対象は、その編集画面が復元で引き継いだ、または正常に退避した文書に限る。未変更の参照キャッシュを理由に別画面の退避を解除しない。退避所有は保存元・文書keyごとに保持し、直列I/O内の成功だけで更新する。観測revisionが一致して内容も変わらない退避は、世代を増やさず完了する。

editingとoriginalは編集退避と比較元のペアとして保持し、ローカル保存済みチェックポイントとは区別する。公開に失敗した世代と既存世代は自動削除しない。current破損時に別世代へ黙って戻さない。

既存オフライン原本と旧退避は削除・書戻ししない。既知形式の変換が必要な場合は所有する取込コピー内で行い、新世代へ取り込む。未知の形式や変換できないデータは推測して読み進めない。

名前だけで帰属していた旧サーバー退避は自動的に現在の接続先へ割り当てない。「旧退避から復元」で候補名・更新時刻・件数を選び、対象の作業コピーを確認する。接続先との由来を証明した表示は行わない。明示復元は同じIDの編集層を置き換えるが、保存済み内容・取得基準・原本は保持する。壊れたペアや取消では新世代へ取り込まない。

管理接続の過去の退避候補は、同じアプリ保存領域のautosaveとmanaged直下の既知作業領域のautosaveだけから読む。binding、lease、サーバー原本を探索しない。別の保存領域へのリンクをたどらず、同名候補も場所を分けて表示する。
