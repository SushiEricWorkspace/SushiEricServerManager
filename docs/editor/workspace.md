# 機能の分割表示とIDタブ

## 表示と移動

接続中のホーム、各エディター、Dashboard、コンソール、サーバー操作、Mod設定、履歴は、同じウィンドウのworkspaceへ表示する。左の機能一覧から選択すると、現在の領域の実寸に応じて右か下へ分割する。分割後の640×220pxを目安にし、現在の領域が不足する場合は分割可能な最大領域を使う。すでに表示中ならその領域へフォーカスする。同じ機能のViewは一つだけ保持する。

機能の見出しを別の領域の左右・上下の端へドラッグすると、その側へ移動する。分割線で比率を変えられる。新規表示時だけ配置先を選び、保存した配置やユーザーが移動した既存領域を自動で並べ直さない。移動では既存のNode、編集データ、履歴、選択、監視購読を再利用し、読込・接続・終了処理を実行しない。機能の終了は見出しの×またはファイルメニューの「この機能を閉じる」で行う。ホームを閉じた場合も左の一覧から再表示できる。ウィンドウ全体の×やAlt+F4は共通hostの終了処理で退避・切断を待ち、ホームの表示有無に依存しない。終了失敗時は編集と接続を保持する。

共通メニューとショートカットはフォーカス中の機能へ切り替わる。機能の移動で入力欄の文字・選択範囲・フォーカスを保持する。IME未確定入力中は機能のドラッグ移動を開始しない。履歴確定のScene監視はそのエディターの入力領域だけを対象にし、Scene離脱時と終了時に解除する。

幅の狭いウィンドウでは既存エディターのサイドバーが本文の幅を占める。500pxなどの小窓で複数エディターを同時に快適表示する保証はなく、上下配置や分割線で作業領域を確保する。Stageの最小幅は引き上げない。本文内部の幅への適応は別の変更で扱う。

## 内側のIDタブ

アイテム・鉱石・ショップ・レシピのエディター内では、サイドバーで開いたIDを横一列に表示する。IDごとのViewは作らず、既存のEditorViewが編集キャッシュ・元データ・履歴・保存処理を管理する。未保存のIDには`*`を付ける。

- 通常のドラッグ、横ホイール、トラックパッドの横スクロール、Shift＋ホイールで列を横移動する。スクロールバーや左右の矢印は表示しない。
- Alt（macOSではOption）を押したドラッグだけを並べ替えとして扱う。列の端では自動スクロールし、マウスを離して順序を確定する。Escape、Scene離脱、ウィンドウのフォーカス喪失でドラッグを取り消す。
- タブ列にフォーカスがあるとき、左右キー・Home・EndでIDを選択する。Alt/Optionと組み合わせると順序を変更する。Deleteまたは各タブの×でIDを閉じる。

IDを閉じる前に入力を確定し、編集内容のバックアップを待つ。失敗時はタブを保持する。タブを閉じても未保存キャッシュと履歴は捨てず、再度開くと利用する。機能そのものの終了、接続終了、保存先への書込みは既存の退避・保存契約に従う。

## 配置の保存

`AppSettings.workspaceLayouts`に、既存のデータサービスの接続識別子をキーとして保存する。オンラインは既存profileの識別子、オフラインは専用workspaceの識別子を使う。テーマやショートカットなど同じ設定ファイルの値を保持する。

保存対象は機能の分割木、方向、比率、アクティブ機能、エディター別ID順序と選択IDである。Node、編集データ、接続情報や認証情報は含めない。変更後200msにまとめて保存し、workspace終了時にも保存する。保存済み配置のない設定ではホームから開始する。

復元時は既存の機能起動・一覧読込経路を使う。現在利用できない機能は配置から除き、一覧に存在するIDだけを戻す。IDやprofile、接続を自動生成しない。接続全体の終了では開いていた配置を保持し、機能を個別に閉じた場合はその領域を配置から外す。

## 検証の区別

分割木とID状態は単体試験、Nodeの同一性・入力・フォーカス・メニュー宛先・退避待ち・解放・設定復元は専用StageのFX試験で確認する。ID列のスクロールと並べ替えはFXイベントで確認する。物理トラックパッド、実OSのドラッグ操作、日本語IME候補選択は自動イベント試験とは区別して扱う。
