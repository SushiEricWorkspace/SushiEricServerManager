# 保存工程と一括保存

## 一括保存

`EditorView.onSaveAll`は入力を確定し、開始時点で未保存の対象ID・編集データ・元データ・保留操作を固定する。データはdeepCopyで取得する。

1. 保存元ごとの編集データ、保存済みチェックポイント、入力退避を固定する。最新サーバーデータの取得は保存とは別操作である。確認ダイアログはJavaFXスレッドで表示する。
2. 全対象の準備後、承認可能な対象の差分をまとめて確認する。準備失敗と対象別の確認キャンセルも表示する。
3. 承認された対象を順番にローカル世代へ保存し、成功した対象だけ保存済みチェックポイント・編集キャッシュ・履歴・保留操作を更新する。未完成データと入力途中の文字列も保持する。各対象のID変更・削除は同一世代で確定する。
4. 保存成功がある場合、最後にローカル保存済みの一覧とディレクトリを1回取得し、サイドバーを1回構築する。一覧更新の失敗でも書き込み済みの対象を未保存へ戻さない。

準備と保存は別々の完了件数／総件数と現在の対象IDを表示する。バックアップ整理中は同じ対象の保存工程を表示する。件数から時間の完了率を推定しない。

処理中は対象画面の編集、再実行、終了を抑止する。同じ接続を使う別画面のストア操作も既存の保存実行状態で抑止する。書き込み開始後の取消や自動再試行は行わない。

## 完了結果

一括保存の戻り値は同期的な成功判定ではない。結果はJavaFXスレッドの完了コールバックで受け取る。

```kotlin
logic.onSaveAll { result ->
    // 書き込み済みのIDは、後処理に失敗していてもresult.savedに残る。
    println("保存済み: ${result.saved.size} 件")
}
```

`BatchSaveResult`は保存済みID、対象別失敗理由、準備中の確認キャンセル、まとめた確認の取消などによる未実行ID、後処理エラーを保持する。結果ダイアログはそれぞれの件数と対象名を表示する。開始できない場合もBUSYまたはNOTHING_TO_SAVEをコールバックへ返す。

一部成功はSAVED_WITH_ERRORS、全対象の書き込み成功・後処理成功はSAVEDとなる。単件保存と一括保存は書き込み、結果のキャッシュ適用、バックアップ整理、一覧更新の工程を共用する。

## 警告修正

単件・全件の警告修正は、入力中の値を確定してから編集データのdeepCopyを取得する。修正は接続ごとの背景I/O実行枠で行い、結果の反映はJavaFXスレッドで行う。

トップバーには処理済みデータ件数／対象データ総数、対象ID、実行中の修正内容を表示する。外部取得を含む修正とローカル退避の待機中は不定進捗を表示し、対象画面の編集・選択変更・再実行・終了を抑止する。全件修正の確認を取り消した場合は、編集内容へ適用せず操作を解除する。

各修正は独立したコピーに実行し、`ValidationRepairResult.Applied`の変更だけを反映する。未対応、失敗、アクションの例外は対象別に報告し、同じ対象や他の対象で成功した修正を保持する。

修正結果は未保存の編集内容となり、ストアへ自動保存しない。変更がある場合はediting／originalと保留操作を既存の非同期バックアップ経路で退避し、その完了まで工程表示を維持する。退避に失敗しても編集キャッシュを保持して操作を解除し、終了操作などで退避を再試行できる。表示更新の失敗も修正結果や退避を取り消さない。

## 保存境界の検証

三状態と保存元の契約は[編集・ローカル保存・取得基準](local-documents.md)を参照する。通信fixtureは明示取得以外のreadと全writeを計数し、保存成功や失敗がremoteへの変更を伴わないことを確認する。

保存の失敗はcodec、current公開、古い文書revisionで確認する。UIでは待機中の応答、重複実行・終了の抑止、一部成功、確認取消、原本保持、再起動復元を確認する。実Stageは通常版と開発版の専用homeで分け、WindowsとmacOSの実行結果を別々に記録する。
