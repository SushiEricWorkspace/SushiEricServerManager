# 戦闘シミュレーター画面

オンライン/オフラインのHomeにある「戦闘シミュレーター」から開きます。同じ画面を再度開くと既存ウィンドウへフォーカスします。計算のためのサーバー接続・保存・アップロードは行いません。

## 入力と実行

- プレイヤーからMob、Mobからプレイヤーの直接近接・直接投射物・直接魔法を選べます。
- プレイヤー基礎能力は技能・装備を含まない値を入力し、技能レベルと装備を別に指定します。基礎値の全項目はCoreのStatsType、Mob能力はEntityStatsTypeの項目に対応します。
- 固定装備は部位ごとに有効化し、種類・ID・固定値・必要技能・倍率・強化を手動指定します。倍率はSelf/All/指定Part（BASE/SKILLを含む）を選びます。既対応リフォージも選択できます。適用可否、技能条件、上限、Selfと部位倍率の計算は既存EquipmentAssembler/Coreへ委譲します。装備値を基礎能力へ重複加算しないでください。
- HP/OverHeal/ST/MP・構え・Block/Parry期限は当事者ごとの現在値です。現在値は非負・小数3桁以内（末尾0除外）を要求し、丸め規則をUIへ複製しません。MobのOverHealは0だけ指定できます。盾と筋力は使用可能な装備と集計済み能力を正本とし、別入力しません。
- BREAKは対象側の値、有効状態とruntime有無を区別して指定します。Mobパリィ設定と最終直接/投射間隔tickも手動指定できます。攻撃者の履歴を古い順に指定し、次の履歴ID・Kind/Effectの固有間隔・特殊効果CDの役割/提供元/effect IDを固定します。sword-cycleはこの履歴からCoreが判定し、別入力しません。
- 命中行は上から同じtickの処理順です。単発も1行のMultipleHit要求を使います。追加時にhitIdを作り、上下移動・再計算では維持します。未命中/OH貫通、Player近接のバニラ会心、Player投射物の矢種/rank/距離、固有間隔を行ごとに指定できます。各行の「現在入力で発射状態を固定」は現在の当事者Snapshot・tickと手入力した発射基本値を保持します。その後の現在値変更とは独立し、解除/再固定だけで更新します。
- 射撃profileは成立済み1射のmetadataです。BOW/標準CROSSBOWは手動装備のmulti/arrowCount/arrowEfficiencyから本数と消費を生成し、行数の不一致は非対応になります。MANUALでは条件と矢消費数を明示します。発射時消費を初期ST/MPから再消費しません。
- 厳密期待値はseedなし、サンプルは指定seedで実行します。初期値や未編集の入力欄もすべて固定要求へ取り込みます。不正な数値文字列は入力エラーとして拒否します。

「計算」で固定要求を作り背景実行します。実行中は入力を固定し、「取消」で値なしの取消状態を表示します。別要求・取消・画面終了・接続切替後の古い完了通知は表示しません。表示済み結果は直前の固定要求の値であり、入力変更後は再計算してください。

## 表示と制約

算出最終ダメージ、純HP減少、OverHeal吸収、適用量を区別します。厳密期待値とサンプルを明示し、取消・非対応・計算上限超過・例外に0ダメージを補いません。サンプルの各行にはhitId、処理状態、HP適用結果、前後HP/OH/ST/MP・構え/CD・間隔/履歴/BREAK、式とPreparationのphaseTrace、抽選の到達/確率/値/成立を表示します。確率は0〜1、抽選値は0以上1未満です。期待値は各行の周辺平均と状態/拒否確率、終端枝の重みと状態を表示し、一意の中間状態や抽選値を捏造しません。詳細は50件単位のページで全行・終端枝を参照できます。比較の行・抽選差も50行単位で参照し、全行の文字列を一括生成しません。

「基準を保持・更新」「比較」「基準解除」で直前の固定要求の結果を比較します。基準は明示操作でのみ変わり、比較のための再計算は行いません。期待値とseed付きサンプルは別モードです。行はhitIdで対応し、追加/削除/順序変更を区別します。削除された基準行も基準の実値・状態を表示し、存在しない側へ0行を補いません。算出/純HP/OH/適用量の差を別々に表示します。基準0の増減率は未定義、取消/非対応/上限超過は数値差なしです。

同tickの指定順だけを評価します。弾道、遅延、ノックバックによる後続衝突、時間進行、成功後効果の実適用は行いません。表示しない入力には既存APIの既定値を使用し、独自の計算式や推定を追加しません。

## 装備の固定取込

保存済みItemは画面に明示したOFFLINE_DIRの絶対パスと公開ID・部位を指定し、「取得・再読込」で読みます。オンライン中も同じローカルtyped読込で、接続先原本を暗黙取得しません。未存在/削除、不正ID/YAML/検証エラー、I/O失敗では直前の有効入力・結果を保持します。

編集中ItemはItem画面の「シミュレーターへ取込」だけが入口です。部位を選び、入力をEnter等で確定して入力欄から離れてから操作してください。編集中のeditable text focus、現存するeditable Spinnerの表示と確定値の不一致、owned popup/モーダル画面、読込/保存/修正中、判定不能を拒否します。有効な数値文字列でも未確定なら取り込みません。拒否理由はItem内に表示し、focus移動・自動確定・dialog・保存・履歴記録を行いません。

mouse pressとボタン上のSpace/EnterはItem Stageのcaptureで既存Scene履歴filterより前にconsumeし、Button action/accessibilityも同じgateを通ります。成功時だけFX上でmodelをdeepCopy/freezeしてからSimulatorへ渡します。元編集値/original/dirty/Undo/redoを変えず、終了時はItem専用filterを解除します。

各部位に取得元、未保存の区分、取得revision、固定Itemの既存PreviewCanvasを表示します。revisionは取得ごとの識別子でファイル更新番号ではありません。候補装備と画面の強化・技能・命中条件を既存#265/#266の入力生成へ通し、全体Readyの場合だけ置換します。非対応効果や近接のオフハンド短剣追撃予約を含む候補、他部位に非対応が残る候補は理由を表示して旧装備・revision・結果・比較基準を保全します。計算や抽選は実行しません。固定取込中は手動の型/能力/技能要求/倍率を使わず、画面で指定した強化だけを#265へ加えます。「手動装備へ戻す」で手動指定へ戻ります。元の編集や保存先の更新では暗黙追従せず、明示取込/再読込だけで更新します。

計算中の取込は拒否します。成功取込後も旧結果は直前の固定要求として残し、再計算を案内します。読込世代・計算世代・接続/終了を照合し、古い背景通知で装備・結果・比較基準を置換しません。

## 構成

`SimulatorView`はFXMLからNode/Controllerを作り、Stageを持ちません。`SimulatorWindowManager`は既存Home経路でStageを一つ管理し、終了時にViewを破棄します。Controllerは`SimulatorInputEditor`から既存型の固定入力を取得し、`SimulatorWorkspace`へ渡します。Workspaceは要求世代と背景実行/取消を扱い、Finishedに要求と既存MultipleHit結果を保持します。後続の詳細表示/比較はこの記録を使い、再計算しません。

既存Utility/AppScreen/common CSSを利用します。分割領域・汎用プレビュー・保存先分離の基盤は追加しません。

## 検証

`SimulatorWorkspaceTest`は実行スレッド、遅い旧世代完了、取消、画面終了、接続切替、例外、値なし表示を確認します。`SimulatorViewTest`はWindows/macOSのJavaFXで実FXML、単一Stage、入力からの1行/複数行計算、行ID、装備のKind適用、盾、全Kind/方向、非対応、取消・解放を確認します。OS未実行は成功と扱いません。テストは実サーバーやSSHへ接続しません。
