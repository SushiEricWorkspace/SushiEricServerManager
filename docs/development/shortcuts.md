# キーボードショートカット

上部「設定」→「キーボードショートカット」で操作とキーを選び、登録・解除・既定値への復元を行います。保存に成功すると、開いた画面のキー実行とメニュー・ボタンの表示へ反映します。入力はCommand（macOS）／Control（Windows）を含むキー、またはファンクションキーを使用します。

`EditorShortcut`を操作IDと既定キーの正本とし、`AppSettings.shortcuts`にはenum名をキーとして差分だけを保存します。キー文字列はJavaFXの`KeyCodeCombination.name`で、`Shortcut+S`はOSのCommand／Controlを表します。項目がない場合は既定値、空文字は割当解除です。解析不能な文字列や競合する設定は実行せず、任意の既定値へ置き換えません。設定画面に無効値・競合を表示し、解除や復元で訂正できます。既存設定の他項目は保持します。

有効範囲はエディターとMod設定です。範囲が重なる操作だけを競合とし、たとえばMod設定だけの再読み込みとエディターだけの操作には同じキーを設定できます。保存は両方で使うため、どちらかとの衝突でも登録できません。

`ShortcutManager.register`の登録先Nodeが文書・機能領域を表します。同じSceneのKEY_PRESSED監視は一つにまとめ、focusOwnerを含む最も近い登録領域へ操作IDを送ります。共通メニューを開いた場合は直前の領域を保持し、メニュー・ボタンも`execute`を通します。Scene移動時は古い監視を解除し、終了時は領域単位で登録を解除します。MenuItem.acceleratorとの二重登録は行いません。

テキスト入力のコピー・切取り・貼付け・全選択・Undo/RedoはJavaFXの標準処理へ委譲します。未確定文字列を含むInputMethodEventを観測した後から確定・キャンセルまたはfocus変更まで、文書操作とイベント起点の履歴確定を行いません。取消した未確定値を文書Undoで復活させず、確定済み入力は履歴へ記録します。InputMethodEvent自体は消費しません。入力方式切替キーと未修飾文字キーの登録を拒否し、TextInput内のControl+Alt入力も奪いません。モーダルが遮断しているownerへはキー・メニューから実行しません。

現行の`SAVE`／`SAVE_ALL`は「現在の保存先」へ保存し、`SYNC`／`SYNC_ALL`は既存の同期処理を維持します。`IMPORT_LOCAL`はローカルデータを編集中データへ取り込む既存処理で、サーバーへ送信する操作ではありません。
`LOCAL_SAVE`はM6、`UPLOAD`と`DOWNLOAD`はM7の完成後に接続する別IDです。設定一覧で準備中と表示し、現在は登録・実行を提供しません。既存保存・同期をローカル保存やアップロードへ読み替えません。

## 検証

キー設定・競合範囲・OS修飾キー・保存表現の純テストと、複数領域のfocus、Scene移動、登録解除、標準編集、composeイベント、モーダル遮断のJavaFX回帰を使用します。testタスクは一時home/appdataへ設定を隔離し、実ユーザー設定を使いません。

Windows（JDK 25.0.4）とmacOS（JDK 25.0.1）で通常版・開発版のbuild、test、installDist、配布検査を実行しました。Windowsは通常652件中641成功・11スキップ、開発45件中44成功・1スキップ、Macは通常652件中630成功・22スキップ、開発45件中44成功・1スキップで、失敗はありません。OS限定・外部接続を必要とする既存試験のスキップを含みます。

両OSの専用fixtureとPlatform.runLater等で、設定入口、登録・解除・競合・復元、再起動保持、既存保存と再読込、作業中Undo/Redoの抑止、代替Redoの割当変更、正常終了を確認しました。実Itemエディターで未確定入力がTextFieldと編集モデルへ反映された状態を作り、取消後に文書Undoで復活しないことを確認しています。確定した入力のUndo/Redoも回帰で検証します。

設定一覧はライト・ダークそれぞれでfocus有無の選択行の可読性を確認し、Windowsの150%・200%指定とMacの実scale 2.0で表示を確認しました。物理IMEの候補選択と実モニター間のDPI移動は未実施です。外部サーバー接続、OS設定変更、jpackage、CI実行を含みません。
